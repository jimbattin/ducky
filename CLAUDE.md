# Ducky
Ducky is a NAM (Neural Amp Modeler) player for the DaisySeed, hosted in a HotHouse pedal platform or a BurningBungalow (a HotHouse fork with an expression pedal jack and a TRS MIDI IN; `../BurningBungalow/`), chosen at build time (`BOARD=`).

It supports 8 presets. Each preset contains a NAM Model (A2-lite only), an optional IR block, a noise gate (off by default) and an optional morph target (another preset). Presets do not track Input/Output gain, compressor, EQ, loop or morph position settings: those are global.

## Rules
- Read `docs/M7_PERFORMANCE.md` before writing or optimising DSP code
- Read `docs/morph-findings.md` before changing the morph's analysis or the trainer, and before testing the morph on the pedal
- `docs/MIDI.md` is generated by `tools/gen_midi_doc.cpp` from `daisy/src/link.h`, `params.h`, `fw_image.h`, `midi.h` and `preset.h`: never edit it, run `make midi-doc` (`make test` fails when it is stale)
- The pedal's load stays under 850 permille of the block period (`docs/ROADMAP.md` "Decisions"); run the bench after any change to the engine, the compiler or its flags (`docs/FIRMWARE.md` "Bench")
- More than one Seed may be attached: address Ducky's by USB path (`--port`, `DK_USB_PORT`) and check `--identity` reports `device 64` before flashing (`docs/FIRMWARE.md`)
- This project lives in a private repo that will one day become public
- The editor follows the conventions of bad_tape (https://github.com/jimbattin/bad_tape)
- Place all documentation in `docs/`, reusable tools in `tools/`
- A finished milestone's record goes in `docs/HISTORY.md`. A new measurement goes in `docs/MEASUREMENTS.md` in place of the figure it replaces: no per-milestone measurement sections in the reference docs

## Commands
Every command runs from the repo root. A new machine or a new Seed: `docs/FIRMWARE.md` "Getting started". Flashing, the log, the bench and the converters: `docs/FIRMWARE.md` "Commands"
- `make test`: host GoogleTest, and the `docs/MIDI.md` staleness check
- `make -C editor test check`: editor and converter tests, tsc, Biome
- `make -C daisy -j`: the firmware (`APP=weight`, `APP=bench` and `APP=latency` build the other images; `BOARD=burningbungalow` builds them for a BurningBungalow)
- `make -C editor serve|html`: the editor with hot reload, or as one file
- `tools/flash_when_ready.sh`: unattended DFU flash over USB-MIDI
- `make -C daisy program-boot`: installs the Daisy bootloader on a new Seed (ROM DFU: hold BOOT, tap RESET)
- `bun tools/pedal.ts list|info|upload|erase|rename|swap|gate|morph|param|status|firmware`: slot and parameter management, and the firmware update (`firmware FILE.bin`, no `dfu-util`), over USB-MIDI while the pedal plays
- `DK_USB_PORT=3-4 make firmware-check`: the firmware update checked unattended on the pedal, through `pedal.ts` and the editor in Chrome (it reflashes the pedal; `BOARD=burningbungalow` on a BurningBungalow; `docs/FIRMWARE.md` "Firmware update")

## IO Configuration
A global loop mode (`loop_mode`, saved in the settings record) picks one of three:
- MISO (default): mono in on L In (the input's tip); dual mono out (L + R identical: L is copied to R)
- Loop pre-model and loop post-model: an effects loop with R Out (the output's ring) as the send and R In (the input's ring) as the return; the pedal plays on L Out only. Insert cables (TRS to two TS) on both jacks

## Signal chain

MISO: L INPUT -> Compressor (OTC-201 or OTA model by `comp_type`, off by default) -> Input trim -> [Preset: NAM Model -> IR] -> EQ (low-cut, 3 bells, high-cut) -> Output volume × [Preset: noise gate gain, detected from L INPUT before the compressor] -> Mute -> L/R Out

Loop pre-model: L INPUT -> Compressor -> Send level -> R Out => [loop pedals] => R In -> Return level -> Input trim -> [NAM Model -> IR] -> EQ -> Output volume × gate -> Mute -> L Out

Loop post-model: L INPUT -> Compressor -> Input trim -> [NAM Model] -> level match × gate × Send level -> R Out => [loop pedals] => R In -> Return level -> [IR] -> EQ -> Output volume -> Mute -> L Out

Morph: a preset with a morph target runs its model and the target preset's model and crossfades their outputs (equal power) at the global `morph` parameter's position (0 %: its own model, 100 %: the target's; its own IR and gate throughout). A second image, the weight build (`make -C daisy APP=weight`), runs one model instead, its weights blended into the target's along a straight line or a trained path: `docs/MORPH.md`

## Controls
- FS1: Mute. LED1 active when not muted; off when muted
- FS2: Next preset (skips empty slots, wraps). LED2 blinks N times for slot N, repeating after 5 s dark. MIDI CC 102 (value 0-7, on EXP's channel over USB, or MIDI IN's channel on a BurningBungalow's MIDI IN jack) selects slot 1-8; an empty slot is ignored
- Knob 1: Input Gain trim, relative (Noon is the model's input calibration from `input_level_dbu`, ±12 dB). Fixed
- Knob 2: Output Volume (Noon is unity). Fixed
- Knobs 3-6, SW1-SW3, EXP (an expression pedal: MIDI CC 11 on the Seed's USB MIDI port, or a BurningBungalow's MIDI IN jack) and, on a BurningBungalow, PEDAL (its expression pedal jack, factory none) are assignable: each drives one parameter of the table (`daisy/src/params.h`) or none. A switch takes only choice parameters. The factory layout (`kFactoryAssign`), the pickup rule and the parameters: `docs/MIDI.md` "Controls", "Parameters"
- A parameter on a control is "What you see is what you get" on the pedal; the editor can set one, and it holds until its control moves
- The assignments and the values are global, and kept across power cycles by an explicit save (the settings record)

## Technology
- Presets (NAM Model + optional IR + noise gate + optional morph block with up to three waypoints) are stored in QSPI Flash (8 × 64 KB slots at `0x90400000`), written slot by slot over USB-MIDI by `tools/pedal.ts` or as a bank image by `tools/preset_bank.ts` over DFU, and parsed into SDRAM at boot and after each slot change
- Parameters (the EQ's sixteen, the compressor's five, the loop's three, the morph) live in one table (`daisy/src/params.h`) that the link sends to hosts
- The last slot and the settings are each kept in a two-copy record in QSPI (`docs/FIRMWARE.md` "Preset store", "Settings record")

## Docs
- `docs/ROADMAP.md`: decisions in force, milestones left, risks
- `docs/HISTORY.md`: finished milestones (what each decided, measured and verified)
- `docs/FIRMWARE.md`: build/flash/log, source layout, threads, memory map, preset store, settings record, log lines, the bench (`APP=bench`)
- `docs/MEASUREMENTS.md`: current load, timing and bench figures from the pedal
- `docs/EDITOR.md`: the browser editor (running it, each tab, link and sync, drafts and saving, source layout, conventions)
- `docs/MIDI.md` (generated): the USB-MIDI SysEx link (commands, parameter table, controls and pickup rule, upload, status stream)
- `docs/NAM_FORMAT.md`: NAM A2 format, A2-Lite shape, forward pass, model binary, converter, reference renders, engine
- `docs/FILTERS.md`: IR convolver, cut filters, noise gate, IR binary and `.wav` converter
- `docs/EQ.md`: the EQ's specification and as-built notes
- `docs/LOOP.md`: FX loop modes (signal flow, cabling, gate placement, fades, the latency image `APP=latency`)
- `docs/MORPH.md`: preset morph as built (crossfade, weight build, analysis, trained paths, formats)
- `docs/morph-findings.md`: preset morph research (what was tried, pedal checks still to do, avenues)
- `docs/compressor-spec.md`: the compressor (circuit analysis, SPICE, DSP model, reference implementation `tools/comp_reference.py`)
- `docs/ota-compressor-spec.md`: the OTA compressor type, Dyna Comp / Ross (circuit, SPICE, DSP model, reference implementation `tools/ota_reference.py`)
- `docs/M7_PERFORMANCE.md`: Cortex-M7 float cost model, rules for DSP kernels, how to measure

## Directories
- `docs/`: Documentation
- `tools/`: Reusable tools
- `daisy/`: Pedal code
- `editor/`: Editor code (Bun + TS + Preact). `src/nam/`, `src/ir/`, `src/preset/`, `src/link/` and `src/morph/` are shared with the `tools/*.ts` tools (`docs/EDITOR.md` "Source layout")
- `models/`: NAM Models (git-ignored)
- `irs/`: Example cab IRs (commercial York Audio packs; git-ignored). Mono 24-bit PCM WAV, 500 ms, in 44.1k/48k/96k folders, plus Kemper `.kipr` (not supported); macOS `._*` and `.DS_Store` files mixed in
- `tests/`: Host GoogleTest; `tests/fixtures/` holds the upstream MIT NAM fixtures and the generated IR, preset, morph and compressor fixtures
- `renders/`: Local reference renders and stimuli (git-ignored)
